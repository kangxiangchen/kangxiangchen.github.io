[Auto]Stitching Photo Mosaics

Chen KangxiangCS180, Project 4 2026-10-26

When a camera only rotates, every photo it takes sees the same rays of light, just cut by a differently tilted image plane. Any two such photos are therefore related by a homography, a 3×3 projective transform, whatever the depth of the scene. In Part A I recover those homographies from points I clicked by hand, warp photos onto a common plane with my own inverse-mapping code, and blend them into mosaics.

Conventions used throughout: a point is (x, y) = (column, row) with pixel centres at integer coordinates, and computeH(p1, p2) returns the H with p2 ~ H p1, i.e. it maps image-1 coordinates into image 2. Photos are downsized so the longer side is 1200 px before any processing.

Part A: Image warping and mosaicing

A.1 Shooting the pictures

I stood in one spot and rotated the phone between shots, with roughly half of each photo overlapping the next. Rotating about the centre of projection is what makes the relation between photos a pure homography regardless of scene depth. Moving the camera instead introduces parallax, which no single homography can undo.

A.2 Recovering homographies

A homography maps p = (x, y, 1) to p' ~ Hp. Fixing the bottom-right entry to 1 leaves 8 unknowns:

x' = (a x + b y + c) / (g x + h y + 1)
y' = (d x + e y + f) / (g x + h y + 1)

Multiplying out the denominator makes each equation linear in the unknowns, so every correspondence gives two rows of a linear system:

[ x  y  1  0  0  0  -x x'  -y x' ] h = x'
[ 0  0  0  x  y  1  -x y'  -y y' ] h = y'

Stacking n correspondences gives a 2n × 8 system Ah = b. Four points determine H exactly, but then every pixel of clicking error goes straight into H, so I click more points and solve the overdetermined system by least squares, minimising ||Ah − b||². Before solving, both point sets are normalised (centroid to the origin, mean distance √2) and H is un-normalised afterwards. In exact arithmetic this gives the same answer, but it keeps A well conditioned: raw pixel coordinates put entries of size 1 next to entries of size 106 (the x·x' terms).

A.3 Warping and rectification

Warping uses inverse mapping. I push the four corners of the input through H to get the output bounding box, then for every output pixel apply H−1 to its location to find where it came from in the input, and read the input there. Looping over output pixels guarantees every one gets a value, so there are no holes. An output pixel whose source lands outside the input gets alpha 0, and that alpha mask is reused for blending.

Nearest neighbour rounds the source location to the closest pixel centre. Bilinear takes the four surrounding pixels and weights them by (1−fx)(1−fy), fx(1−fy), (1−fx)fy and fxfy, where fx and fy are the fractional offsets. Both are written from scratch and vectorised with NumPy.

To test the warp I rectified photos of rectangular objects: click the object's four corners and map them to a rectangle with the object's true aspect ratio. Only a margin around the object is shown, because points near the vanishing line map towards infinity.

Averaged over my rectifications, nearest neighbour took 0.05 s and bilinear 0.14 s, about 2.6× slower: bilinear reads four pixels and does several multiply-adds per output pixel where nearest neighbour reads one. In the zoomed crops, nearest neighbour shows jagged, stair-stepped edges, because neighbouring output pixels jump between whole input pixels, and where the warp stretches the image each source pixel is copied into a block. Bilinear gives smooth edges and gradients at the cost of slight blurring. For a final mosaic the extra time is negligible next to the quality gain, so I use bilinear everywhere else.

A.4 Blending into a mosaic

For each set I keep the middle photo unwarped as the reference and warp the others into its image plane. Homographies are computed between neighbouring photos and chained, for example H0→2 = H1→2H0→1, and a photo to the right of the reference uses the inverse of its pairwise H. The canvas is the union of all warped bounding boxes, and every photo is warped into it in one pass.

Each photo gets a weight map equal to its distance to its own nearest border (1 at the centre, falling linearly to 0 at the edges), warped along with the colours. Pasting photos on top of each other (overwrite) leaves hard seams. Plain feathering, the weighted average ΣwiIi / Σwi, hides the seams but ghosts any fine detail that is misaligned by a pixel or more. My final results use two-band blending (Brown and Lowe): each photo is split into a low band (Gaussian blur, σ = 2.0 px, computed only from valid pixels so the empty canvas doesn't bleed in) and a high band (photo minus low band). The low band is feathered, so exposure differences fade smoothly. The high band at each pixel comes from the single photo with the largest weight, so fine detail is never averaged and cannot ghost.

A.5 Bells and whistles: cylindrical projection

A planar mosaic stretches badly towards the sides as the field of view grows, since the plane is tangent at the reference view and the stretch grows like tan θ. Instead I project onto a cylinder of radius f around the camera, and sample directly from the original photos so nothing is resampled twice. For output pixel (u, v), θ = u/f and height h = v/f give the ray (sin θ, h, cos θ). That ray hits the reference image plane at (f tan θ + cx, f h / cos θ + cy), which Hi−1 maps into photo i, where I sample bilinearly. Blending is the same two-band scheme. I set f = 0.95 × image width, which matches a phone's main camera held upright. A pure pan becomes a pure horizontal shift on the cylinder, so vertical lines stay vertical and the sides are no longer stretched.
