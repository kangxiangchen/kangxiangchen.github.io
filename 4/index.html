[Auto]Stitching Photo Mosaics

CS180 Project 4 · Kangxiang Chen

Part A stitches photos using correspondences I clicked by hand: recover the homography between each pair of photos, inverse-warp them onto a common image plane and blend.

Part A

A.1 Shooting the pictures

I stood in one spot and rotated the phone between shots, with roughly half of each photo overlapping the next. Rotating about the centre of projection is what makes the relation between photos a pure homography regardless of scene depth; moving the camera instead introduces parallax, which no single homography can undo. Photos are downsized so the longer side is 1200 px before processing.

A.2 Recovering homographies

A homography maps a point p = (x, y, 1) to p' ~ Hp, with

x' = (a x + b y + c) / (g x + h y + 1)
y' = (d x + e y + f) / (g x + h y + 1)

where the bottom-right entry is fixed to 1, leaving 8 unknowns. Multiplying out the denominator makes each equation linear in the unknowns, so every correspondence gives two rows:

[ x  y  1  0  0  0  -x x'  -y x' ] h = x'
[ 0  0  0  x  y  1  -x y'  -y y' ] h = y'

Stacking n correspondences gives a 2n by 8 system Ah = b. Four points determine H exactly, but click errors of a pixel or two then go straight into H, so I click more points and solve the overdetermined system by least squares, minimising ||Ah - b||2. Before solving, both point sets are normalised (centroid to the origin, mean distance sqrt(2)) and H is un-normalised afterwards. This gives the same answer in exact arithmetic but keeps A well conditioned, since raw pixel coordinates put entries of size 1 next to entries of size 106 (the x x' terms). computeH(im1_pts, im2_pts) returns H mapping image-1 points into image 2.

A.3 Warping and rectification

Warping uses inverse mapping. I push the four corners of the input through H to get the output bounding box, then for every output pixel compute H-1 of its location to find where it came from in the input, and read the input there. Looping over output pixels guarantees every one gets a value, so there are no holes. Pixel centres are at integer coordinates; an output pixel whose source lands outside the input gets alpha 0, and this alpha mask is reused for blending.

Nearest neighbour rounds the source location to the closest pixel centre. Bilinear takes the four surrounding pixels and weights them by (1-fx)(1-fy), fx(1-fy), (1-fx)fy and fxfy, where fx, fy are the fractional offsets. Both are implemented from scratch and vectorised with NumPy.

To test the pipeline I rectified photos of rectangular objects: click the object's four corners and map them to a rectangle with the object's true aspect ratio. Only a margin around the object is shown, because points near the vanishing line map towards infinity.

Speed vs quality. Averaged over my rectifications, nearest neighbour took 0.06 s and bilinear 0.12 s (2.0x slower): bilinear reads four pixels and does several multiply-adds per output pixel where nearest neighbour reads one. In the zoomed crops, nearest neighbour shows jagged, stair-stepped edges, because neighbouring output pixels jump between whole input pixels. Where the warp stretches the image, each source pixel is copied into blocks. Bilinear produces smooth edges and gradients, at the cost of slight blurring. For a final mosaic the extra time is negligible compared to the quality gain, so I use bilinear everywhere else.

A.4 Blending into a mosaic

For each set I keep the middle photo unwarped as the reference and warp the others into its image plane. Homographies are computed between neighbouring photos and chained: for example H0→2 = H1→2H0→1, and the photo on the right of the reference uses the inverse of its pairwise H. I take the union of all warped bounding boxes as the canvas and warp every photo into it in one shot.

Each photo gets a weight map equal to its distance to its own nearest border (1 at the centre, falling linearly to 0 at the edges), warped along with the colours. Pasting photos on top of each other (overwrite) leaves hard seams. Plain feathering, the weighted average ΣwiIi/Σwi, hides the seams but ghosts any fine detail that is misaligned by a pixel or more. My final result uses two-band blending (Brown and Lowe): each photo is split into a low band (Gaussian blur, σ = 2.0 px, computed only from valid pixels so the black canvas doesn't bleed in) and a high band (photo minus low band). The low band is feathered so exposure differences fade smoothly; the high band at each pixel is taken from the single photo with the largest weight, so detail is never averaged and cannot ghost.

A.5 Bells and whistles: cylindrical projection

A planar mosaic stretches badly towards the sides as the field of view grows, since the plane is tangent at the reference view and the stretch grows with tan(θ). I instead project onto a cylinder of radius f around the camera, and do the inverse sampling directly from the original photos so nothing is resampled twice. For output pixel (u, v), θ = u/f and height = v/f give the ray (sin θ, height, cos θ); that ray hits the reference image plane at (f tan θ + cx, f·height/cos θ + cy), which Hi-1 maps into photo i, where I sample bilinearly. Blending is the same two-band scheme. I set f = 0.95 × image width, chosen by eye; this is close to a typical phone main camera, whose horizontal field of view is roughly 65 to 70 degrees. A pure pan becomes a pure horizontal shift on the cylinder, so vertical lines stay vertical and the sides are no longer stretched.
